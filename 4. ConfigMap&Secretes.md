
# CONFIGMAP

CONFIGMAP store information which can be used in application in later point of time. For ex. there is backend application which needs DB User, DB Port, DB Connection etc. So we cannot hardcode this information in application. So we can store this informaiton in CONFIGMAP and application can access this information which is stored in POD.
We can use CONFIGMAP as ENVIRONMENT VARIABLE AND VOLUME MOUNT both.

NOW, CONFIGMAP data is saved in etcd. So we can not save sensitive data in CONFIGMAP like DB user, DB password. It can be easily hacked.

So store non-sensitive data in CONFIGMAPS & sensitive data in SECRETES.

When data is stored in SECRETES, it is saved in etcd in encrypted form at REST.

So if it is hacked, it will be in encrypted form and can not be read by others.
