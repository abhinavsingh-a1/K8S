# Phase 2: Terraform modules + Ansible (enterprise layout)

The HA kubeadm cluster from Phase 1, built the way a platform team would:

| Concern | How |
|---|---|
| Infrastructure | Terraform **modules** (`network`, `ssh-key`, `security-groups`, `k8s-nodes`, `nlb`) composed per environment in `live/<env>` |
| Terraform state | Remote, in an encrypted and versioned **S3 bucket**, with S3-native locking (`use_lockfile`) |
| Inventory | **Dynamic**: the Ansible `aws_ec2` plugin discovers nodes by EC2 tags; no hand-written IP lists |
| SSH key | Generated by Terraform, stored in **AWS Secrets Manager**, fetched on demand; never in the repo |
| App and cluster secrets | **Ansible Vault** (`vault.yml`, encrypted, committed); password file outside the repo |
| Secrets in Kubernetes | Created from Vault with `no_log`, and **encrypted at rest in etcd** (secretbox key from Vault) |
| Configuration | Small single-purpose **roles**, numbered **playbooks** per step, `site.yml` runs them all |

- Phase 2 Terraform and Ansible walkthroughs: see `../docs/README.md`

## Prerequisites (WSL, Ubuntu)

Work inside the Linux filesystem: `cp -r /mnt/g/.../k8s-ha-project ~/`. On `/mnt/...` drives, Ansible ignores `ansible.cfg` and ssh rejects the key; `run.sh` refuses to run there.

```bash
# Terraform >= 1.10
wget -O- https://apt.releases.hashicorp.com/gpg | sudo gpg --dearmor -o /usr/share/keyrings/hashicorp.gpg
echo "deb [signed-by=/usr/share/keyrings/hashicorp.gpg] https://apt.releases.hashicorp.com $(lsb_release -cs) main" | sudo tee /etc/apt/sources.list.d/hashicorp.list
sudo apt update && sudo apt install -y terraform pipx unzip openssl

# Ansible + the libraries the aws_ec2 inventory needs
pipx install --include-deps ansible && pipx inject ansible boto3 botocore && pipx ensurepath

# AWS CLI v2, kubectl
curl -sSo awscliv2.zip https://awscli.amazonaws.com/awscli-exe-linux-x86_64.zip && unzip -q awscliv2.zip && sudo ./aws/install
sudo snap install kubectl --classic
aws configure && exec $SHELL
```

## Run it

```bash
cd ~/k8s-ha-project/phase2-terraform-ansible

# one-time
./scripts/run.sh deps          # amazon.aws collection into ansible/collections
./scripts/run.sh bootstrap     # S3 state bucket, writes live/dev/backend.hcl
./scripts/run.sh vault-init    # ~/.ansible/vault/k8s-ha-dev.pass + encrypted vault.yml

# Steps 1-8
./scripts/run.sh image         # Step 1 (or Phase 1 step1 script on Windows)
./scripts/run.sh plan          # Steps 2-3: review what will be created
./scripts/run.sh apply         # Steps 2-3: apply exactly that plan
./scripts/run.sh fetch-key     # SSH key from Secrets Manager -> ~/.ssh/k8s-ha-dev.pem
./scripts/run.sh configure     # Steps 4-7: ansible-playbook site.yml
./scripts/run.sh status        # health + proof that Secrets are encrypted in etcd
./scripts/run.sh destroy       # Step 8
```

**Back up the vault password** (`~/.ansible/vault/k8s-ha-dev.pass`) in a password manager. Without it, `vault.yml` can't be decrypted.

## Everyday Ansible commands

```bash
cd ansible
ansible-inventory --graph                          # what the dynamic inventory found
ansible-playbook playbooks/30-app.yml              # redeploy the app only
ansible-playbook site.yml --check --diff           # dry run
ansible-vault view inventories/dev/group_vars/all/vault.yml
ansible-vault edit inventories/dev/group_vars/all/vault.yml   # e.g. add Docker Hub creds
ansible-vault rekey inventories/dev/group_vars/all/vault.yml  # new vault password
```

## Adding an environment (e.g. prod)

1. `cp -r terraform/live/dev terraform/live/prod`, then edit `terraform.tfvars` (`environment = "prod"`, its own `vpc_cidr`).
2. `cp -r ansible/inventories/dev ansible/inventories/prod`, then change `tag:Environment` in `aws_ec2.yml`.
3. `ENV=prod ./scripts/run.sh bootstrap && ENV=prod ./scripts/run.sh vault-init`.
4. Add `prod@~/.ansible/vault/k8s-ha-prod.pass` to `vault_identity_list` in `ansible.cfg`.
5. `ENV=prod ./scripts/run.sh plan` and so on. Run Ansible with `-i inventories/prod`.
